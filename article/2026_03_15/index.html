Golangのリンターと設定について

  • リンターというのは書いたコードに対して誤りがないか、その言語に対してよくない書き方をしていないかなどを検知するツールです。
  • 特にgolangではgolangci-lintという便利なツールがあるので、かつ自身が実務で使っていたのでその設定や使い方についてメモします。

インストール方法は自身はMacなのでbrew install golangci-lint実行で完了。

公式のドキュメントにありますが、以下４つのファイル形式で設定できます。

.golangci.yml
.golangci.yaml
.golangci.toml
.golangci.json

飛ばしたいファイルやディレクトリがある場合は以下のように設定項目に記載します。 ここではyamlで例を記載します。

# skip dirs
linters:
  exclusions:
    paths:
      - src/external_libs
      - autogenerated_by_my_lib

# skip files
linters:
  exclusions:
    paths:
      - '.*\.my\.go$'
      - lib/bad.go

linterではどのlinterを有効にするかをenbale, disable項目を追加して記載します。

linters:
  disable-all: true
  enable:
    - megacheck
    - govet
  enable-all: true
  disable:
    - maligned
    - prealloc
  # 後述するが、ここにlinterのより詳細な機能を設定する項目を記載する。
  settings:
    option: value

disable-allやenable-allなどを使って全てのliner有効無効にする設定もかけます。 とく何もいじらない場合はデフォルトで有効になっているlinterがあるので、上記のdisable-allを使って一旦全てのlinterを無効にし、そこから自身のプロジェクトに合う設定を選び、enableに追加していくということもします。 私は実務ではそのようにして記載していました。

例としてどのようなlinterがあるか記載します。

errorCheckとはエラーチェックがしっかり行われているかについてをチェックする項目です。 以下のように機能詳細に設定した場合、ファイルに記載しlinterを有効にします。 errorCheckの中でもより詳細に設定したいなどの場合に以下のようにして記載していきます。

  • check-type-assertionsは型アサーションによるエラーチェックの有無
  • check-blankはブランクを使用してerrチェックを無視している場合の検出

ドキュメントに説明がありますがこのようにオプションを設定することでより詳細にlinterを設定できます。

linters:
  settings:
    errcheck:
      # Report about not checking of errors in type assertions: `a := b.(MyStruct)`.
      # Such cases aren't reported by default.
      # Default: false
      check-type-assertions: true
      # report about assignment of errors to blank identifier: `num, _ := strconv.Atoi(numStr)`.
      # Such cases aren't reported by default.
      # Default: false
      check-blank: true

実行コマンドとしては、golangci-lint runで実行できます。 特定のlinterのみを動かすコマンドもあり、golangci-lint run --disable-all -E <実行したいlinter名>とすることで実行できます。
