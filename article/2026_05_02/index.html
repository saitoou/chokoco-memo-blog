ラズパイを使用した音声通話検証

Chokoco

5月 2, 2026

Raspberry Pi Zero 2 Wにイヤホンを繋ぎ、Bluetooth経由でスマホ通話する

はじめに

  • Raspberry PiやM5StackとスマートフォンをBluetoothで接続し音楽を聴いたり、デバイスに録音機能を持たせたりなどを行う記事は見かけるのですが、Raspberry PiやM5Stackに接続したイヤホン経由で通話を行うという記事を見たことがなかったため興味本位で検証してみようと思い、本記事のような取り組みをしました。

  • 多少のBluetooth関連の知識はありますが（本数冊程度読んだくらいですが、、）音声制御や通話制御の知識はないため生成AIと自身のググりで進めています。お見苦しいところもありますが、温かい目でみていただけますと助かります。

やること

自身大学で電気工学を学んだが数年前の話なので忘れているため、回路設計などは諦めて すでにあるモジュール（機器）を組み合わせて検証していきます。

  1. M5Stack or Raspberry Piを使用し、Bluetoothでスマホに接続します。
  2. スマホに電話をかけて、M5Stack or Raspberry PiをBluetooth接続しているスマホで電話に出て通話時の機器選択でM5Stack or Raspberry Piを選択します。
  3. M5Stack or Raspberry Piに接続しているイヤホン経由で会話し、通話先の相手の声を聞き取ることができ、こちら側の声も聞こえたら達成とします。

本検証に使用したデバイスたち

  • M5Stack Basic v2.6, M5Stackオーディオモジュール(STM32G030), Raspberry Pi Zero 2 W, Jabra Evolve2 40 SE, 通話に使用するスマホ, マイク機能付きのイヤホン(TRRS), TP-Link USB Bluetooth Adapter

検証

  • 以前ESP32を使用し、スマホにBluetooth接続して操作するものを作ったことがあったので今回の検証もESP32を使えばいけそうと思いESP32を最初に選択しました。
  • たまたまスイッチサイエンスのサイトでM5Stackオーディオモジュール(STM32G030)を見かけ、これを使って生成AIでコードを作ればいけるのではという軽い気持ちで検証を開始しました。

M5Stack Basicとオーディオモジュールを組み立て、Bluetooth接続でスマホと接続し、オーディオモジュールに刺したイヤホンで通話するイメージです。

iPhone
↓ Bluetooth
M5Stack Basic
↓
オーディオモジュール
↓
イヤホン（IN/OUT TRRS）

※ESP32のコード書き込みの環境構築については以下のリンクを参照してください。

  • https://docs.espressif.com/projects/esp-idf/en/v5.4.1/esp32/get-started/index.html

bluetooth接続についてはesp-idfのリポジトリのexampleの中にあるbluedroidを使用して実装しました。

次に通話機能を持たせるためbluedroidの中にある、hfp_hfのREADME.mdを参考にしてコードを実装します。

※基本的にスマートフォンとBluetoothイヤホンの通話において必要な機能としてはBluetooth Classic機能が必要です。（Bluetooth Low EnergyもLE Audioがありますが今回は除きます。）このBluetooth Classicの要素の一つとしてHFP(ハンズフリープロファイル)があり、それを今回のデバイスたちに入れ込む必要があります。Bluetoothのプロファイルについては以下の記事がわかりやすいので参考にしてください。

  • https://www.musen-connect.co.jp/blog/course/trial-production/profile-basic/

これらのコードを生成AIを使用しながら実装しM5Stackに書き込み後、通話を行い声が聞こえるか試します。 以下のような構成をとって通話ができるのではという考えをもとにこのようにして検証しました。

iPhone
= HFP AG（Audio Gateway / 電話側）
        ↑ Bluetooth HFP
M5Stack Basic
= HFP HF（Hands-Free / ヘッドセット側）

最初はM5StackとiPhoneのbluetooth接続はできても、通話先の相手の音声が聞こえない、こちらの側の声も届かない状態となったため、調整していきます。

ここからは通話を行った際に通話先の相手の声が聞こえることと、こちら側の声が届くことを分けて実装し、検証します。 通話先の相手の声が聞こえる際の手順としては、以下のような流れになります。

HFP接続 → 受信データ取得 → PCM化 → I2S再生

通話先のスマホから受信した圧縮された音声データを生の音データに戻す流れを表しています。

main/bt_hfp.cでHands Free Profileの生成を行い、main/audio_route.cでbt_hfp.cから取得したPCMを再生する機能に渡しています。main/audio_codec.cでオーディオモジュールを初期化・設定しI2Cで音声サンプルをcodecに送り、codecでアナログにしてイヤホンで出力しています。 ノイズはありますが、通話先の相手の声を聞くことができました。

通話先の相手の音声は聞き取ることができましたが、こちらのマイクの音は入っていません。

次はマイクの音の方に取り組みましたが、入力音声の品質が安定せずノイズがずっと出てしまいました。 通話先の相手に音声を届ける機能はあれこれと試してみましたが、試すうちに以前できていた相手の声を聞く方の機能が壊れてしまったりなどして、なかなか先に進まずに詰まってしまいました。

考えられる原因として以下のことが特にあるのではと思いました。

  • リアルタイムでの受信・送信の難しさ
  • M5Stack Basic自体のリソースの制約
  • 送信側の実装の難しさ

以下のissueでも通話の音声を聴くことはできていますが、こちら側の声を届けることについてはまだできていないように見えます。

検証機を変更する

ChatGPTと壁打ちを行い検証機を変更することにしました。M5StackからRaspberry Pi Zero 2 Wに変更しました。 Raspberry Pi Zero 2 WはLinuxを動かせるため、Linuxに標準搭載されているBlueZが使用できます。 BlueZはHFP/SCO周りの実績が多く、今回M5Stackで詰まっていた音声経路の問題が解決できるかもしれないと思い導入しました。（値段もM5Stackに比べて安いため導入もしやすいですし。）

※BlueZについては以下の記事がわかりやすいです。

  • https://qiita.com/ffmatsu/items/b7ca6a944b5a1ea9c7a6

※SCO: 通話の際に使われる音声通信専用の規格のことです。A2DPは音楽用でSCOが電話用。

やることとしては以前と変わらず、以下のような構成で検証します。

iPhone
↓ Bluetooth
Raspberry Pi Zero 2 W
↓
イヤホン

最初は調べたところPipeWireがLinuxにおいて音声周りの管理を行なっていたので使えるのではと思い試しました。 以下の方の記事からもいけそうと思い試しましたが、結果としてはスマートフォンに接続は成功しましたが、特に音も何も聞こえずでした。

  • https://gkiagia.gr/2025-02-20-pipewire-telephony/

原因としては音声をやり取りを行う経路の確立ができておらずで、api.bluez5.transportログの中にあったこの項目が空として出ていたためでした。

ofonoをインストールし試してみます。 以下のQiitaの記事を読んでいた際にHFP関連のAPIはofonoを使用することと記載があったためofonoとBlueZの組み合わせで試しました。

  • https://qiita.com/ffmatsu/items/b7ca6a944b5a1ea9c7a6#classic%E9%96%A2%E9%80%A3

イメージとしては、以下のようにofonoで最初にできていなかった通話の制御などをofonoが担う感じです。

BlueZ  = Bluetooth通信
oFono  = 通話制御（HFPロジック）
PipeWire = 音声処理

今回は通話先相手の音はノイズがありましたが、聴くことができました。しかしこちら側の声を通話先の相手に届けることはできませんでした。

以下のラズパイの公式コミュニティのやり取りを見ると現状の技術スタックでは通話先の相手に声を届けることが難しいのがわかりました。

  • https://forums.raspberrypi.com/viewtopic.php?t=189710

M5Stackの時と同じでやはり音声を届けることがかなり壁になりました。電話に出た際に音声入力機能がすぐに落ちたりするなどのケースが頻繁にありました。 これも音声経路の確立がうまくいかずにiPhone側で通話デバイスでないと認識されることやリアルタイム通話が遅延により崩れ、サンプルレートの不整合など様々な要因がありました。

ここでRaspberry Pi Zero 2 Wに内蔵されているBluetoothだとSCO周りが不安定で難しいのではと思い、USB Bluetooth Adapterを導入することにしました。またBlueALSA, ALSAをインストールし手動でルーティングすることにしました。 これらを行なったことによりノイズはありつつも音声通話できたので一連のコマンドを記載します。

$ sudo apt install -y bluez bluez-tools ofono bluez-alsa-utils alsa-utils ffmpeg

必要なライブラリをinstallし、以下のようにしてペアリングコマンドを打ちます。

$ bluetoothctl
$ power on
$ agent on
$ default-agent
$ discoverable on
$ pairable on

Bluetooth接続確立後、

$ trust <繋いでいるスマホのMACアドレス>

通話先に声を届けるコマンドと通話先の音声を受け取るコマンドを通話後に音声の経路を確立するため以下のコマンドを打ちます。

これにより、通話先相手の音声が聞こえます。

$ bluealsa-aplay --profile-sco <繋いでいるスマホのMACアドレス>

これにより、通話先の相手に自身の声が聞こえます。

$ arecord -D plughw:0,0 -t raw -f S16_LE -r 16000 -c1 | \
aplay -D "bluealsa:DEV=<繋いでいるスマホのMACアドレス>,PROFILE=sco" \
-t raw -f S16_LE -r 16000 -c1

Bluetooth通話音声を手動でルーティングしていますが、双方の音声を聞いて通話できるようになりました。

結論

  • BlueZ, ofono, BlueALSA + ALSAで手動ルーティングで通話が実現しました。 (USB Bluetooth Adapterを使用してSCOの安定を行いつつ。)

検証をおえて

  • 最終的に音声通話ができるよう？になりましたが、日常的に使えるかといえば少々難しい音質でした。今回の検証で音声通話の知識や通信の確立など、スマホを使った通話をするための勉強になりました。 ワイヤレスイヤホンを作る上では元々あるモジュールを組み合わせて作ることもできるのはわかりましたが、使う上では圧倒的に市販品には敵わないので、改めて市販品の凄さを実感しました。

  • 音声通話の用語ややり方、bluetoothを使用した通話などはなかなかまとまっていないのでキャッチアップする上で生成AIが大活躍でした。
